# 01 — Product Requirements

## 1. Student

### Student registration
- Student can create an account.
- Required fields are validated.
- Duplicate accounts are rejected.

### Student profile
- View/update permitted profile information.
- Student cannot change protected administrative fields.

### Classes
- View enrolled classes.
- View class timetable.
- View class resources.
- Access class announcements.
- Access class discussion/chat rooms.

### Assessment
- View assignments.
- Submit assignments before/within allowed deadline.
- View submission status.
- Take quizzes where permitted.
- View grades and grade history.

### Attendance
- View attendance records for enrolled classes.

### Notifications
Student can receive notifications for relevant events such as:
- New assignment
- Assignment deadline
- New grade
- Class announcement
- New class material
- Chat/message activity
- Attendance-related event

---

## 2. Lecturer

### Classes
- Create/manage classes where authorized.
- Assign/manage enrolled students.
- View class roster.
- Assign class timetable.
- Manage class resources.

### Assessment
- Create assignments.
- Create quizzes.
- Review submissions.
- Grade manually.
- View grade history.
- View class performance.

### Attendance
- Record attendance.
- Correct attendance where authorized.
- View attendance statistics.

### Communication
- Post announcements.
- Participate in class discussions.
- Create/use permitted class chat rooms.

---

## 3. Class

A class can contain:

- Lecturer
- Students
- Timetable
- Resources
- Assignments
- Quizzes/exams
- Attendance records
- Announcements
- Discussion threads
- Chat rooms

---

## 4. Analytics

System should support:

- Student performance
- Class average
- Attendance percentage
- Assignment completion rate
- Quiz performance
- Students at risk of falling behind

Analytics must respect role permissions.

---

## 5. Administration

Admin can:

- View admin dashboard
- Manage students
- Manage lecturers
- Manage courses/classes
- Assign roles
- Manage permissions
- Disable/enable accounts
- Review system activity where permitted

---

## 6. Chat rooms

Chat rooms can be associated with a class.

Example:

Class: Database Systems
    ├── General chat
    ├── Assignment 1 discussion
    └── Exam preparation

Users must only access rooms they are authorized to access.

Messages should contain:
- Message ID
- Room ID
- Sender ID
- Message content
- Created timestamp
- Optional edited timestamp
- Optional reply/reference information

---

## 7. Notifications

Notifications are generated by system events.

Example:

Assignment created
        ↓
Notification service
        ↓
Students enrolled in class
        ↓
In-app notifications
        ↓
Optional realtime delivery

The system should distinguish between:
- Unread
- Read
- Archived/deleted where supported

---

## 8. Non-functional requirements

- Authentication required for protected endpoints.
- Authorization must be checked on the backend.
- Validate all incoming data.
- Never trust frontend role information.
- Use transactions for multi-step database operations.
- Avoid exposing sensitive information in logs.
- API responses should use predictable structures.
- Realtime connections must be authenticated.
